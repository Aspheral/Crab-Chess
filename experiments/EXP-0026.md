## Hypothesis and applicability

Post-SF18 upstream Stockfish commit `6e4c77f51d09062180fbc2b9befd294abe412633` (2026-09-04), "Fix bug in nodestime", clamps the time-management `scaledTime` value to at least 1.

The upstream failure mode is:

1. nodestime mode is enabled;
2. `availableNodes` is consumed to zero (or below one `npmsec` quantum);
3. a subsequent `TimeManagement::init()` starts with non-zero GUI clock time, then converts that clock to the exhausted `availableNodes` value;
4. integer division produces `scaledTime == 0`;
5. `log10(scaledTime / 1000.0)` becomes `-inf`, which can flow through time constants and eventually cause undefined behavior when a non-finite floating-point value is converted to an integer `TimePoint`.

Current accepted Crab contains the same relevant control flow and formula, so the fix is directly applicable.

## Candidate change

`engine/src/timeman.cpp`:

```diff
-const TimePoint scaledTime  = limits.time[us] / scaleFactor;
+const TimePoint scaledTime  = std::max(TimePoint(1), limits.time[us] / scaleFactor);
```

Candidate implementation commit: `023cd86ea4129f0b770ab9b2ebf1aa19856ae2d7`.

The existing Stockfish copyright header, GPLv3 terms, and upstream-derived-file notice are unchanged. The implementation remains under the Crab namespace and public Crab Chess identity.
