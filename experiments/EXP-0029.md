# EXP-0029 — Convert movetime under nodestime

Status: ACTIVE — correctness / UCI time-limit semantics; no Elo claim.

## Hypothesis

When Crab runs with the `nodestime` option enabled, `TimeManagement::elapsed()` reports elapsed work in nodes, while `SearchManager::check_time()` compares that value directly against `limits.movetime`. Current accepted Crab leaves `limits.movetime` in milliseconds, so `go movetime N` is effectively interpreted as `N` nodes instead of `N * nodestime` nodes.

Convert `limits.movetime` from milliseconds to nodes during `TimeManagement::init()` whenever nodestime is active, before the no-clock early return. This is adapted from official Stockfish commit `ceb059eb48fb8e556df8feff6f8a24e45d03fa11` (2026-08-19), "Convert movetime when nodestime is in force".

## Applicability / duplicate check

Accepted Crab at `dff78780c450443a3719a49419524ac04c0044c7`:

- sets `useNodesTime = npmsec != 0`;
- converts clock time/increment to nodes later in `TimeManagement::init()`;
- does not convert `limits.movetime`;
- has `SearchManager::check_time()` compare nodestime-backed elapsed work with `limits.movetime`.

The defect is therefore present and the upstream fix is directly applicable. No open Crab engine experiment or stack duplicates this hypothesis. Open PRs #32 and #40 are infrastructure-only.

A separate post-SF18 Syzygy PV-extension correctness change (`19a02f44e1bfee44b5a00acf6e812c643b8fd54c`) was also screened and appears applicable, but it is deliberately not being run in parallel with EXP-0029.
