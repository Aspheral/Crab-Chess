# EXP-0027 — preserve explicit movestogo horizon in cyclic controls

## Classification

**ACTIVE — time-management correctness / practical strength candidate.**

This candidate is intended to prevent avoidable losses on time in cyclic time controls. It is not being treated as a generic additive Elo point estimate: the canonical 3+0.03 strength screen does not exercise explicit `movestogo`, so any ordinary screen is contextual rather than proof of the targeted effect.

## Hypothesis and applicability

Post-SF18 upstream Stockfish commit `4d65257b0f8fd8179b81fb88176c4d6eaea94a9c` (2026-09-01), "Avoid reducing move horizon in cyclic time controls", changes the sub-second horizon reduction so it only applies when `movestogo == 0`.

The upstream evidence reported:

- 40/1 cyclic control: master lost 557 games on time, fixed candidate lost 0; 1,984 games total;
- 40/10 cyclic control: master lost 116 games on time, fixed candidate lost 0; 10,000 games total.

Accepted Crab has diverged from upstream to a centi-move horizon (`centiMTG`), but retains the same problematic control condition: whenever `scaledTime < 1000`, Crab overwrites an explicitly supplied `movestogo` horizon. Therefore the upstream patch does not apply byte-for-byte, but its guard is directly applicable to Crab's current formula.

## Candidate change

`engine/src/timeman.cpp`:

```diff
-    // If less than one second, gradually reduce mtg
-    if (scaledTime < 1000)
+    // If less than one second, gradually reduce mtg.
+    // In cyclic time controls keep the explicit movestogo horizon.
+    if (scaledTime < 1000 && limits.movestogo == 0)
         centiMTG = int(scaledTime * 5.051);
```

Candidate implementation commit: `8a76716181c21c45c5cf975c710b925298dd7972`.

The inherited Stockfish copyright header, GPLv3 terms, and upstream attribution are unchanged. The code remains in the Crab namespace and the engine's public identity remains Crab / Crab Chess.
