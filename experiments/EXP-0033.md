## Hypothesis
`Position::do_null_move()` copies the prior `StateInfo` with `memcpy`, including `capturedPiece`. A null move captures nothing, so leaving the prior capture in the child state can expose stale capture metadata to any unguarded consumer. Clearing `newSt.capturedPiece` immediately after the copy should improve correctness without changing ordinary legal move semantics.

## Current Crab applicability
Current Crab contains `StateInfo::capturedPiece` and `Position::do_null_move()` performs the same full-state copy pattern. The candidate is therefore applicable as a one-line, isolated adaptation:

```cpp
newSt.capturedPiece = NO_PIECE;
```
