# EXP-0028 — integer move-horizon arithmetic

## Status

ACTIVE — isolated candidate under validation. Do not merge into accepted Crab main unless matched-resource evidence justifies promotion.

## Hypothesis

Current Crab still carries the centi-MTG arithmetic inherited from SF18-era time management. Replace it with integer move-to-go arithmetic, adapting official Stockfish commit `82908e0fd68a3a717e6152f66a297ecc97d9a6e9` to current Crab while preserving EXP-0027's explicit cyclic `movestogo` guard.

The upstream change passed large STC/LTC/sudden-death non-regression tests and removes fractional centi-MTG arithmetic. On Crab, the candidate is intentionally isolated so any effect from the coarser sub-second sudden-death horizon is measured rather than assumed neutral.

## Applicability check

Applicable with adaptation. Accepted Crab still used `centiMTG`, including the same time-left and cyclic-control scaling structure targeted by the upstream change. Crab additionally contains the promoted EXP-0027 condition `limits.movestogo == 0`; EXP-0028 preserves that condition rather than restoring the older upstream behavior.

The candidate changes only `engine/src/timeman.cpp` engine semantics. Existing GPLv3 text, Stockfish copyright/upstream attribution, Crab namespace, executable identity, UCI identity, build naming, network files, and website branding are untouched.

## Candidate diff

- `centiMTG` becomes integer `mtg` capped at 50 moves.
- Sub-second sudden-death reduction becomes `int(scaledTime * 0.05)` and remains disabled when explicit `movestogo` is present.
- `timeLeft`, cyclic `optScale`, and `maxScale` use direct integer-move arithmetic.

## Required validation

Before classification, require:

- clean GCC and Clang builds;
- Crab UCI identity and handshake;
- deterministic/reproducible Crab bench;
- ASan/UBSan correctness smoke;
- unchanged NNUE/network and opening checksums;
- canonical matched-resource strength screen against accepted Crab and untouched SF18;
- artifact-backed compiler, CPU, Threads/Hash, TC, concurrency, opening/adjudication policy, binary checksums, W/D/L, score, Elo/CI or SPRT state, and PGNs.

The standard 512-game screen is triage only. A promising unresolved result must be replicated; a clear negative is rejected; a tiny positive/non-harmful unresolved result may become STACK-ELIGIBLE.
